# CLAUDE.md

Reusable, config-driven landing page system for **Gurugram Estate Pvt Ltd**, a HARERA-registered
real estate agent in Gurugram. Each project is one data file plus one asset folder in
`src/content/projects/<slug>/`. Components never contain project-specific content.

Commands: `npm run dev`, `npm run build` (Astro build + compliance scan), `npm run check`
(astro check + compliance), `npm test` (Vitest), `npm run new-project -- <slug>`,
`npm run build:production` (launch blockers become errors).

The master prompt and blueprint are the source of truth. The rules below apply to every session.

## 1. Non-negotiable rules

### Factual integrity

- Never invent RERA numbers, approvals, prices, sizes, possession dates, amenities, distances, awards, reviews, testimonials or developer endorsements.
- Every factual claim in the UI comes from the project data file and carries `source` and `verifiedOn`. Facts missing either are hidden and logged as a build warning (`isVerified()` in `src/lib/compliance.ts`).
- No fake urgency: no countdown timers, "only X units left", "prices rising tomorrow", or fake visitor counters.
- TBD values render as hidden or "On request" and are listed in each phase report. Never invent a replacement.

### RERA compliance (Haryana)

- If `rera.status` is not `registered`, the page runs in REGISTER INTEREST MODE:
  - No prices, price ranges, price per sq ft, payment plans, booking amounts.
  - Banned anywhere in rendered pages: "EOI", "expression of interest", "booking", "book now", "pre-launch offer", "limited units", "price sheet", "payment plan", "official site", "official website". Enforced by a post-build HTML scan (the required disclosure sentence is allow-listed).
  - CTAs read "Register interest", "Get launch updates", "Talk to an advisor".
  - Status line: "RERA registration: not yet registered. We will share pricing and plans only after registration."
- If `rera.status` is `registered`, show the RERA number and https://haryanarera.gov.in in the hero, configurations section and footer.
- Every page shows the agent disclosure: "Gurugram Estate Pvt Ltd is an independent real estate agent, HARERA agent registration no. {agent_rera_number}. This is not the developer's official website." Use "authorized channel partner of {developer}" only with written authorization. Generated by `agentDisclosure()`.

### Branding and assets

- Gurugram Estate Pvt Ltd is an authorized L&T Realty channel partner for L&T Sector 86 (owner confirmed 2026-10-18). Co-branding: L&T Realty logo leads in the nav, hero eyebrow names the developer, footer shows "Authorized channel partner of L&T Realty". The site must still never claim to BE L&T Realty or the official website; the disclosure stays on every page.
- `developer.authorizationProof` must record the agreement reference and date (production build fails without it).

- Developer logos, renders, master plans and floor plans only if `developer.authorizedToUseLogo` / `authorizedAssets` is true AND the file is in `assets.yaml` with `license: authorized` and `fromDeveloper: true`.
- Every image must be listed in `assets.yaml` with `license` in [owned, authorized, licensed, open]. Build fails on any unlisted image or `license: unknown`.
- Renders are captioned "Artist's impression". Non-project photos and illustrations are captioned "Representative image".
- Never copy text, images, code or layout from the reference sites.

### Privacy and security

- No API keys or secrets in frontend code. All secrets in Cloudflare environment variables.
- Never store name, phone or email in localStorage, sessionStorage, cookies, URLs, analytics events or logs.
- Only non-personal campaign data (UTM parameters, click IDs, landing path, referrer host) may be kept in sessionStorage.

### Writing style

- US spelling. No em-dashes in any user-facing text (build fails). Short, concrete sentences.
- Banned phrases: "nestled", "in the heart of", "unparalleled", "world-class", "redefine luxury", "elevate your lifestyle", "a perfect blend", "seamless", "unmatched", "dream home awaits", "experience the epitome".

### Build-time failures (scripts/check-compliance.mjs + zod refinements)

1. `priceFromInr` present and `rera.status !== "registered"`.
2. Banned register-interest term in a non-registered project's built HTML.
3. Em-dash (U+2014) in built HTML text.
4. Image referenced but not in `assets.yaml`, unlisted file in `images/`, or `license: unknown`.
5. Developer logo or render used while the matching authorization flag is false.
6. A page with zero or more than one `<h1>`.
7. `seo.title` > 60 chars or `seo.description` > 155 chars.
8. `agent_rera_number` TBD (also domain TBD, dummy phone numbers) on a published project: warn in dev, fail in production (`--production` or `CF_PAGES_BRANCH=main`).

## 2. Tech stack

- Astro 7 (`output: "static"`), TypeScript strictest. Zod v4 via `astro/zod`.
- No React/Vue/Svelte. Interactivity uses small vanilla TypeScript modules.
- Content collections (glob loader) with zod schemas in `src/lib/schemas.ts`, shared by `src/content.config.ts` and the compliance script.
- `astro:assets` `<Picture>` for AVIF + WebP, explicit width and height, `loading="lazy"` except the hero.
- Fonts self-hosted via Fontsource: Fraunces Variable (display) and Manrope Variable (body), Latin only, `font-display: swap`, both preloaded (`src/components/Fonts.astro`).
- GSAP + ScrollTrigger for motion only, dynamically imported after `load`, skipped under `prefers-reduced-motion`.
- Fully static hosting (Cloudflare Pages). NO backend, no serverless functions, no database (owner's decision, 2026-10-18).
- Leads: the enquiry form posts from the browser straight to the CRM's PUBLIC lead-capture endpoint via `src/scripts/api.ts` (the only external API call), configured by `PUBLIC_CRM_LEAD_URL`. Never put a private API key or token in the frontend or in any `PUBLIC_` variable. The CRM must allow CORS from the site domain. Adapt to a CRM by editing only `toCrmBody()` and `readCrmResponse()`.
- Spam: client-side honeypot (`company_website`) and a 3 s minimum fill time; dedupe via `idempotency_key` in the CRM. Redirect to thank-you only after the CRM returns 2xx.
- `@astrojs/sitemap`. Vitest, Playwright, @axe-core/playwright, Lighthouse CI. ESLint + Prettier. npm.

## 3. Folder structure

```
src/content.config.ts          collections: site, projects, projectAssets ("_" folders ignored)
src/content/site/settings.yaml business settings (section 0 keys)
src/content/projects/_template/ copy via npm run new-project -- <slug>
src/content/projects/<slug>/   project.yaml, assets.yaml, images/
src/lib/schemas.ts             zod schemas (single source of truth)
src/lib/compliance.ts          rules: verification, disclosure, banned words, HTML scan
src/lib/data.ts                getSettings, getProjects, getProjectBundle (asset guard)
src/lib/format.ts, color.ts    INR/sq ft/dates; WCAG contrast + accent ink
src/layouts/, src/components/, src/scripts/, src/styles/, src/pages/
src/lib/validation.ts          form rules + consent wording (CONSENT_VERSION)
src/scripts/api.ts             CRM connector + types (LeadSubmission, SubmitResult, ...)
src/scripts/enquiry.ts         modal: open by intent, validate, submit, states
src/scripts/attribution.ts     first-touch UTM/click IDs in sessionStorage (no PII)
.env.test                      fake CRM URL for Playwright (intercepted)
scripts/check-compliance.mjs, scripts/new-project.mjs
docs/, tests/unit|e2e|a11y
```

URLs: `/`, `/<slug>/`, `/<slug>/thank-you/` (noindex), `/disclaimer/`, `/privacy-policy/`, `/terms/`. Lowercase, trailing slash.

## 4. Conventions

- Accent: `--accent` (raw, for rules/icons/large display text) and `--accent-ink` (darkened to 4.5:1 at build time by `darkenToContrast`) for small text.
- FAQ answers may use tokens `{{rera_status}}` and `{{agent_disclosure}}`, resolved at render time.
- Work phase by phase; stop and report after each phase. Commit after each phase.
